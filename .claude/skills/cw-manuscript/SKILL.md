# 取材後の原稿制作（cw-manuscript）

## 手順

1. **整形**: `bun run cw transcript <文字起こし> --job <ID> --map "話者1=聞き手,話者2=<対象者名>" [--glossary 誤→正.json]`
   → `jobs/<ID>/manuscript/` に `transcript_clean.md` `transcript_report.md` `keypoints.md` `outline.md`
2. `transcript_report.md` の誤変換候補を文脈で判定し、確実な誤りだけ `transcript_clean.md` を修正。判断がつかないものはユーザーに一覧で確認する。
3. 取材中のメモ（数字・固有名詞）があれば `manuscript/memo.md` に保存（校正時の事実照合に使われる）。
4. **要点・エピソード**: `keypoints.md` のスコア上位を起点に、記事の核になるエピソードを3〜5個選び、理由とともに提示。
5. **構成案**: `outline.md` の仮見出しを、実際の発言に合わせて書き換える（リード＋見出し3〜4本＋締め、各見出しの目安文字数付き）。`prep/tone.md` の見出しスタイルに合わせる。ユーザーまたはクライアントの確認が必要なら、ここで止める。
6. **初稿の下書き**: 構成案に沿って `manuscript/draft_v0.md` を書く。
   - 文体・一人称・語尾は `prep/tone.md` と `rules.json` に従う
   - **発言内容を改変・創作しない**。発言の要約・言い換えは可、ただし事実（数字・年数・部署名・固有名詞）は文字起こしのまま
   - 補いたい情報が文字起こしにない場合は `【要確認：〜】` と書いて残す
   - 最終的な文章はユーザーが仕上げる前提の「下書き」であることを冒頭コメントで明示
7. **タイトル・見出し案**: `bun run cw titles --person <名> --role <職種> --company <社名> --phrase "<印象的な一言>" --years "入社3年目"` で型を出し、それをベースに各型2案ずつ、見出しも各見出し2〜3案を出す。
