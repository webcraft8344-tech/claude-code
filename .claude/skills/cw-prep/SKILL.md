# 受注後の準備（cw-prep）

## 手順

1. 雛形を作る: `bun run cw prep <案件ID> --role "<取材対象者の職種・役割・年次>" [--minutes 60]`
   → `jobs/<ID>/prep/` に `questions.md` `hearing.md` `checklist.md` `research.md`、`jobs/<ID>/rules.json`（表記ルール雛形）を作成。
2. **企業調査**（WebSearch / WebFetch を使う）:
   - 公式サイト・採用サイト・企業理念／ミッション・プレスリリース・既存の社員インタビュー記事を調べる
   - `research.md` の各欄を埋める。**すべての記述に出典URLを付ける**。推測には「（推測）」と明記
   - 正式社名・サービス名・部署名の表記を `rules.json` の `companyNames` に登録
3. **トーン分析**: 既存インタビュー記事の本文を WebFetch で取得して scratchpad に保存し、
   `bun run cw tone <file...> --job <ID>` → `prep/tone.md`。結果を「執筆ルール」としてユーザーに要約。
4. **質問リストの仕上げ**: `questions.md` を調査結果に合わせて調整する（企業理念や既存記事で触れられていない論点を足す、既存記事と重複する質問は切り口を変える）。取材時間内に収まる問数にする。
5. **メール下書き**:
   - `bun run cw mail interview-request --job <ID> --contact <担当者名> --interviewee <対象者> --dates "10/1(水) 10:00-11:00,10/2(木) 14:00-15:00"`
   - 他の種別: `schedule` / `interview-confirm`（--url 会議URL）
   - 出力を読んで、クライアントとのこれまでのやりとりに合わせて敬語・文面を整える。送信はユーザーが行う。
6. `hearing.md` でクライアントに確認すべき項目のうち未確認のものをユーザーに伝える。

## 注意

- 取材対象者の個人情報（氏名・顔写真・SNS）を調査対象にしない。調べるのは企業の公開情報のみ。
