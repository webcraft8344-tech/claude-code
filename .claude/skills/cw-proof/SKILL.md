# 校正・品質チェック（cw-proof）

## 手順

1. クライアントの表記ルールを確認・更新: `bun run cw rules <案件ID>`（`jobs/<ID>/rules.json`）
   - `companyNames` 正式社名と誤表記 / `ngWords` / `replacements` / `preferred` 推奨表記 / `targetChars` / `sectionRatios` / `style`
   - クライアント共通ルールは `bun run cw rules <クライアント名>` で `clients/<名>.rules.json` に置ける
2. 機械チェック: `bun run cw proof <原稿.md> --job <ID> [--memo 取材メモ]`
   → `jobs/<ID>/proof.md`（重要度付き指摘一覧・見出し別文字数・事実照合）
   - 取材メモ未指定時は `manuscript/memo.md` → `manuscript/transcript_clean.md` の順で自動照合
3. 機械チェックでは拾えない点を原稿を通読して確認し、`proof.md` 末尾に「目視チェック」として追記:
   - 文脈上の誤字・脱字、主語と述語のねじれ、同じ内容の重複
   - 発言の意図が変わる要約になっていないか（文字起こしと突き合わせ）
   - 採用記事としての配慮: 特定の属性（年齢・性別・国籍・家族構成・障害の有無）を条件のように読める表現、長時間労働の美化、根拠のない待遇表現
4. 修正案は「行・修正前・修正後・理由」の表でユーザーに提示し、**承認されたものだけ**原稿に反映する（勝手に書き換えない）。
5. 🔴要修正 がゼロ、事実照合の不一致がすべて説明済みになったら完了。

## 補足

- 求人広告規制の検出は注意喚起であり法的判断ではない。判断に迷う表現はクライアントに確認するよう伝える。
